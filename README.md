# RedeemNow

**Instant liquidity for tokenized real-world assets, priced by risk.**

Built for Monad Blitz Mumbai V4 — track: Onchain Finance & Trading.

A holder of a tokenized RWA cannot exit before the issuer settles, which takes days. RedeemNow buys
that pending redemption and pays USDC in the same block, at NAV minus a spread. Liquidity providers
fund the vault and earn the spread. A keeper collects par from the issuer at settlement.

The spread is the product. It decomposes into four separate risks, and the app shows you all four:

```
spread = base + utilisation(u) + timeRisk(vol, √horizon) + credit(creditBps)
```

## What is actually novel here

Most RWA demos quote a fee. Three things here are harder to find:

**1. The spread names its own reasons.** Credit is priced explicitly, calibrated to an observed
number: Maple Finance carries $47M of defaulted loans against a $1.23B active book, a 3.8% realised
default rate (Dune × RWA.xyz, 2025). Watch credit's share of the spread move across the book:

| Redemption | Spread | of which credit | credit's share |
|---|---|---|---|
| 1,000 rTBILL (treasury) | 6 bp | 2 bp | 33% |
| 5,000 rJAAA (AAA CLO) | 32 bp | 15 bp | 47% |
| **5,000 rCREDIT (private credit)** | **476 bp** | **380 bp** | **80%** |
| 300 rTSLA (equity) | 371 bp | 25 bp | 6.7% |

Same engine throughout. On equity the spread is volatility-driven; on private credit it is
default-driven. Every figure above is produced by running the sequence on chain — see
[`docs/DEMO.md`](docs/DEMO.md).

**2. It refuses trades.** Each asset carries an exposure cap as a fraction of the book
(`totalAssets × maxExposureBps / 10000`). Ask for too much of one name and the transaction reverts
with `ExposureCapExceeded` — *even when the vault has idle capital*. Pricing risk is table stakes;
declining concentration is what a trading desk does.

**3. Losses land on everyone at once.** `markImpaired` calls `absorbLoss`, which reduces
`outstanding` with no matching rise in `idle`. `totalAssets` falls and every LP's share price drops
**in the same transaction**. There is no interval in which an informed LP can withdraw ahead of a
loss the protocol already knows about, so the bank-run incentive does not exist.

## Run it yourself

Everything below works on a fresh clone with no prior setup beyond the prerequisites.

**Prerequisites:** [Foundry](https://getfoundry.sh), Node ≥ 22.12, pnpm 10.

```bash
git clone https://github.com/SatyamDev803/RedeemNow.git
cd RedeemNow
pnpm install
./scripts/start.sh --fresh
```

That one command starts a local chain, deploys all contracts, seeds a 100,000 USDC book, starts the
keeper, and serves the app at **http://localhost:3000**. It prints the addresses it deployed.

Stop everything with `./scripts/stop.sh`.

> `--fresh` resets the chain. Use it before a demo. Without it the script reuses whatever is already
> running and leaves its state alone — which is right mid-session, because per-asset caps scale with
> the book and a silent reset changes every number on screen.

Then connect any injected wallet to `http://127.0.0.1:8545` (chain 31337) and import Anvil's first
account. That key is public and ships with Foundry:

```
0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
```

**Follow [`docs/DEMO.md`](docs/DEMO.md)** — nine steps, in order, with the exact figure each one
produces. Order matters: spreads and caps depend on what is already on the book.

## How it fits together

```
web/              Next.js 16 dashboard — Overview, Holder, LP, Admin
keeper/           settles due receivables; simulates NAV drift
packages/shared/  chain config, generated ABIs, deployment addresses,
                  and a BigInt mirror of the pricing maths
contracts/
  RWARegistry     per-asset NAV, settlement window, volatility,
                  credit premium, exposure cap, eligibility
  LiquidityVault  ERC-4626 over USDC. advance / settle / absorbLoss / recoverLoss
  RedemptionBridge  quote, redeem, settle, markImpaired, recoverImpaired
  MockIssuer      stands in for a real issuer's redemption queue
  lib/Pricing.sol pure spread maths, mirrored in TypeScript
```

### Contract surface

| Function | What it does |
|---|---|
| `quote(token, amount)` | The full decomposition — every term, the payout, and remaining capacity |
| `redeem(token, amount, minPayout)` | Sell the pending redemption, receive USDC now |
| `settle(id)` | Collect par from the issuer; LPs take the spread, treasury takes its fee |
| `markImpaired(id)` | Write the receivable off; every LP repriced in the same transaction |
| `recoverImpaired(id, usdc)` | The workout path, when a defaulted position pays partially |
| `deposit` / `withdraw` | ERC-4626, limited to idle capital |

Eligibility is enforced: `rPRIV` is registered but not redeemable, and reverts
`NotEligibleRedeemer`. Real issuers — BUIDL, OUSG, USDY, Superstate — only redeem for KYC'd
qualified investors, so a protocol that has not done that onboarding cannot front these assets at
all. That is the moat, and the demo shows it failing on purpose.

## Deliberately not built

Recorded as decisions, with the evidence, in
[the design spec](docs/superpowers/specs/2026-09-18-redeemnow-design.md) §9:

- **Borrow / LTV against RWA collateral.** The larger market — $833M of syrupUSDC (30%+ of supply)
  is already deployed as DeFi collateral, while WTGXX sees flows on only 17% of days. Same pricing
  engine: the spread becomes the LTV haircut. Needs liquidation machinery and an oracle.
- Term-structured PD × LGD, replacing the flat credit term ([why it is flat](docs/superpowers/specs/2026-09-18-redeemnow-design.md) §4.5).
- Issuer attestation for impairment, replacing the permissioned `RISK_ADMIN_ROLE` call.
- A secondary market for the receivables themselves.

On competition, stated plainly rather than discovered on stage: **Circle's USYC already sells
capacity-limited instant redemption for a fee.** The difference is that issuer-run redemption cannot
scale past the issuer's own balance sheet and prices risk by fiat rather than by market. See §10.
